# خطة معالجة إشعارات الهاتف خارج الموقع وإصلاح مزامنة StudyVault

خطة عمل متكاملة لحل مشكلتي وصول الإشعارات إلى نظام الهاتف عبر تقنيات Service Worker وتطبيقات الويب التقدمية (PWA)، وإصلاح تعثر سحب ومزامنة بيانات StudyVault من سحابة Firebase داخل متصفح Chrome وتطبيق Obsidian بخاسرة Surfing.

## القرارات المؤكدة وخيارات المعالجة

> [!IMPORTANT]
> تم تأكيد تفضيلاتك في مرحلة الاستيضاح كالتالي:
> - **الإشعارات خارج المتصفح**: الاعتماد على مشغل الـ Service Worker وإشعارات نظام التشغيل القياسية مع دعم تثبيت الـ PWA لضمان وصول التنبيهات إلى الهاتف حتى بعد إغلاق تبويب كروم.
> - **مزامنة StudyVault على كروم وأوبسيديان**: معالجة تعثر سحب بيانات السحابة عبر توفير مسار اتصال مباشر ومرن (Universal REST Fallback + Firebase SDK) وتطبيع هياكل البيانات المتشعبة التي يحولها Firebase لمصفوفات فارغة.

---

## 1. نظرة عامة والهدف الأساسي

- **الهدف الأول (إشعارات الهاتف)**: ضمان ظهور تنبيهات انقطاع الدراسة وتذكيرات المؤقتات كإشعارات نظام فعلية (System Notifications) على شاشة الهاتف حتى بعد مغادرة المتصفح، ومعالجة الخطأ الشائع في كروم أندرويد الذي يمنع `new Notification()` التقليدية ويشترط `ServiceWorkerRegistration.showNotification()`.
- **الهدف الثاني (StudyVault في كروم وأوبسيديان)**: تمكين المستخدم من سحب بيانات الدراسة وحفظها بسلاسة من سحابة Firebase داخل كلٍ من متصفح Google Chrome وبيئة Obsidian Surfing (التي تفرض قيود أمان مشددة على حزم ES Modules والاتصال بمواقع gstatic الخارجية)، مع تصحيح تحويل المفاتيح العددية (`chapterLectures` و `lectureProgress`) لمنع أي تجميد للواجهة.

---

## 2. تجربة المستخدم والتفاعل البصري

1. **تجربة الإشعارات وتنبيهات الهاتف**:
   - عند طلب الإشعارات في لوحة التحكم، يتحقق النظام من تسجيل الـ Service Worker ويطلب الإذن بنقرة واحدة.
   - عند إطلاق أي إشعار (سواءً كان فحص انقطاع أو تذكير أو تجربة)، يتم إرسال الإشعار عبر `registration.showNotification(...)` برمز الأيقونة والاهتزاز وشارة التطبيق، ليظهر في لوحة إشعارات الهاتف العلوية.
   - عند النقر على إشعار الهاتف، يفتح تطبيق "إنجاز" فوراً ويتم تفعيل التبويب المطلوب عبر معالج `notificationclick` داخل `sw.js`.
   - توفير زر فحص وتشخيص واضح لحالة إشعارات PWA في نافذة الإعدادات.

2. **تجربة StudyVault وسحب النسخة السحابية**:
   - عند الضغط على زر "⬇️ سحب من Firebase"، يظهر مؤشر حالة لحظي وواضح: `⏳ جاري الاتصال والتحقق من السحابة...`.
   - محاولة الجلب أولاً عبر السحابة، وفي حال بيئات Obsidian Surfing المقيدة أو بطء الـ SDK، يتم الانتقال الفوري للـ REST API المباشر لجلب النسخة بأمان وبدون أي خطأ `NOT_INITIALIZED`.
   - تطبيع تلقائي للبيانات المستلمة وتحديث فوري لكروت المواد ونسب التقدم مع ظهور رسالة نجاح خضراء: `✅ تم جلب أحدث نسخة من Firebase بنجاح!`.

---

## 3. القرارات التقنية والمفاضلات

- **قرار إشعارات الأجهزة المحمولة**:
  - *النهج المعتمد*: استبدال استدعاء `new Notification()` داخل `admin.js` بآلية مزدوجة تبدأ بـ `navigator.serviceWorker.ready.then(reg => reg.showNotification(...))` وتتراجع إلى المنشئ التقليدي للأجهزة المكتبية فقط.
  - *السبب*: متصفح Google Chrome على هواتف Android يمنع منعاً باتاً استدعاء `new Notification()` مباشرة خارج الـ Service Worker، وتثبيت التطبيق كـ PWA مع مشغل الخدمة يضمن بقاء معرف التطبيق نشطاً في نظام التشغيل.

- **قرار مزامنة StudyVault في بيئات التشغيل المختلفة**:
  - *النهج المعتمد*: محرك مزامنة هجين (Hybrid Engine) يدعم Firebase Realtime Database SDK الرسمي، وفي حال فشل تهيئته (مثل حالة Obsidian Surfing المقيدة لبروتوكولات الأمان) يتم استخدام HTTPS REST Fetch المباشر بدون الاعتماد على مكتبات خارجية.
  - *السبب*: بيئة Obsidian Surfing تعزل الأطر الداخلية (iframes) وتمنع وصول ملفات الـ module القادمة من CDNs، بينما بروتوكول HTTPS البسيط يمر بسلاسة ويوفر قراءة وكتابة مؤكدة 100%.

- **قرار تطبيع بيانات الفصول والمحاضرات**:
  - *النهج المعتمد*: إنشاء دالة `normalizeStudyVaultState(data)` تعيد تحويل المصفوفات ذات المؤشرات `[null, 15]` إلى كائنات جافاسكربت صحيحة `{ "1": 15 }` وتضمن وجود الحقول الأساسية قبل تمريرها لـ `render()`.
  - *السبب*: منع أي انهيار صامت في دوال الحساب والرسم عند سحب البيانات من السحابة.

### خطوات التنفيذ المحددة:
1. **تحديث مشغل الخدمة `sw.js`**:
   - إضافة مستمع أحداث `notificationclick` لفتح النافذة والتركيز عليها عند لمس الإشعار في الهاتف.
   - إضافة مستمع لرسائل الصفحة لتفويض إطلاق الإشعارات عبر الـ Service Worker.
2. **تحديث إدارة التنبيهات في `js/admin.js`**:
   - تعديل `triggerInactivityNotification` و `testInactivityNotification` لتفعيل إشعارات الـ Service Worker أولاً على الهواتف.
   - ضبط خصائص الإشعار (vibrate, badge, icon, tag) لدعم شاشات القفل وشريط التنبيهات.
3. **تطوير مرونة المزامنة في `studyvault.html`**:
   - بناء مسار سحب مباشر عبر REST API ليعمل داخل Obsidian و Chrome دون أي تبعية للموديولات الخارجية.
   - تطبيع كائنات `lectureProgress` و `chapterLectures` لمنع أخطاء العرض بعد السحب.
   - إظهار تشخيص دقيق في شريط الحالة السحابي وتحديث واجهة المستخدم فورياً.
4. **التحقق والاختبار**:
   - فحص بناء المشروع وتشغيله واختبار استدعاءات الـ API محلياً.
